Расширение для VS Code, которое следит за lock-файлом проекта, сравнивает объявленные зависимости с установленными пакетами и предлагает установить обнаруженные изменения. Работает с npm, yarn, pnpm и bun, а также с несколькими открытыми проектами одновременно.

## Установка

```sh
code --install-extension pagyew.murkvan
```

Либо найдите **Murkvan** на панели расширений VS Code.

## Требования

- VS Code версии 1.96 или новее.
- Проект с `package.json`, одним из поддерживаемых lock-файлов (`package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `bun.lock`/`bun.lockb`) и уже существующей папкой `node_modules`.
- Соответствующий пакетный менеджер, доступный в `PATH`.

## Возможности

- **Следит за lock-файлом.** Как только `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml` или `bun.lock`/`bun.lockb` меняется — чаще всего сразу после `git checkout` — Murkvan проверяет, совпадает ли установленное с объявленным.
- **Синхронизация в один клик.** Если обнаружено расхождение, уведомление предлагает **Install packages** (только изменения) или **Reinstall everything** (полная переустановка в духе `npm ci` — на случай, когда расхождение глубже, чем видно в верхнеуровневом сравнении). Для yarn и pnpm доступна только полная переустановка, так как их команда `add` всегда переписывает `package.json`.
- **Учитывает ветку.** Murkvan запоминает, что уже было синхронизировано для каждой Git-ветки, поэтому возврат на уже синхронизированную ветку не требует повторной проверки.
- **npm, yarn, pnpm и bun** — определяется автоматически, без дополнительной настройки.
- **Поддержка мультирут-воркспейсов и монорепозиториев.** Каждый lock-файл в воркспейсе отслеживается как отдельный проект, включая участников монорепозитория.
- **Панель ожидающих изменений.** Дерево во вкладке Explorer показывает, что именно рассинхронизировано — установленную версию, объявленный диапазон и действие установки для каждого пакета по отдельности или для всех сразу.
- **Автоматизация — только по желанию.** Автоустановка всего (`murkvan.autoInstall`), доверие к отдельным проектам ("Always install for this project"), либо запуск команды после каждой синхронизации (`murkvan.postSyncCommand`) — удобно для `prisma generate` и подобных задач.
- **Поддержка Arc.** Если Arc установлен, Murkvan также следит за его staging-областью, поскольку Arc не уведомляет обычные файловые наблюдатели.

Одна запись в статус-баре отражает состояние всех проектов сразу, а прогресс, обнаруженные изменения и логи всегда доступны через канал вывода **Murkvan**.

## Команды

| ID команды                  | Назначение                                  |
| --------------------------- | ---------------------------------------- |
| `murkvan.showOutputChannel` | Открыть лог расширения                 |
| `murkvan.installPackages`   | Установить ожидающие изменения пакетов (спросит, какой проект, если открыто больше одного) |
| `murkvan.checkPackages`     | Сравнить пакеты прямо сейчас для всех открытых проектов, без изменения lock-файла |
| `murkvan.reinstallAll`      | Переустановить всё дерево проекта из его lock-файла (спросит, какой проект, если открыто больше одного) |
| `murkvan.stopAutoInstalling` | Отменить ранее сделанный выбор "Always install for this project" (спросит, какой проект, если открыто больше одного) |
| `murkvan.installAllPending`  | Установить всё, что показано в панели **Pending changes** |

## Настройки

| Настройка                            | По умолчанию  | Назначение                                                     |
| ---------------------------------- | -------- | ----------------------------------------------------------- |
| `murkvan.logLevel`                 | `info`   | Насколько подробно вести лог в канал вывода (`off`/`info`/`debug`) |
| `murkvan.showOutputOnError`        | `false`  | Открывать канал вывода при каждой записанной ошибке        |
| `murkvan.includeDevDependencies`   | `true`   | Сравнивать `devDependencies` наравне с `dependencies`          |
| `murkvan.autoInstall`              | `false`  | Устанавливать обнаруженные изменения сразу, без предварительного вопроса |
| `murkvan.postSyncCommand`          | `""`     | Команда, которая выполняется в директории проекта после каждой успешной синхронизации |

## Устранение неполадок

Убедитесь, что в корне воркспейса есть манифест и lock-файл, что зависимости хотя бы раз были установлены, и что `npm` доступен в `PATH`. Запустите **Murkvan: Check packages**, чтобы сравнить пакеты по требованию, затем откройте канал вывода **Murkvan** и посмотрите записанные пути и ошибки.

## Разработка

```sh
git clone https://github.com/pagyew/vscode-murkvan.git
cd vscode-murkvan
npm ci
npm run compile
```

Используйте уже настроенный [.vscode/launch.json](.vscode/launch.json), чтобы запустить Extension Development Host.

| Команда               | Назначение                               |
| --------------------- | ------------------------------------- |
| `npm run watch`       | Пересборка и проверка типов при изменениях     |
| `npm run check-types` | Проверка типов                            |
| `npm run lint`        | Проверка исходников линтером                     |
| `npm test`            | Запустить unit- и интеграционные наборы тестов   |
| `npm run test:unit`   | Запустить только unit-тесты (без загрузки VS Code) |
| `npm run package`     | Собрать production-сборку расширения |

Unit-тесты в `src/test/unit` покрывают модули, не импортирующие `vscode`, и запускаются под обычным Mocha. Интеграционные тесты в `src/test/integration` запускаются внутри экземпляра VS Code, загружаемого через `@vscode/test-cli`.
